# III-1-01 문제의 상태와 구조화 수업 설계

교과서(비상교육) 93~96쪽 / 폴더 `03-algorithm-programming/01-problem-state`

## 1. 개념적 렌즈

**렌즈:** 추상화(abstraction)

**왜 이 렌즈인가:** 교육과정 교과 관통 개념표에서 추상화는 알고리즘과 프로그래밍의
핵심 개념이고, III 영역의 핵심 아이디어("알고리즘은 다양한 설계 전략을 통해…",
"자동화를 고려해 설계된 알고리즘은…")가 모두 추상화 위에 서 있다.
II에서 쓴 '표현'을 계속 이어받는 방법도 있었으나, 표현은 04(효율성 비교)에
닿지 않아 III-1 전체를 묶지 못한다. 여기서 렌즈를 갈아타고 '표현'은 03에서
보조 개념으로 재등장시킨다.

**III-1 네 소단원의 일반화 축** — 렌즈 하나 아래 네 축을 미리 갈라둔다.
02의 소단원 제목이 「문제의 추상화」라 렌즈와 겹치는데, 축을 나눠두면
02는 "추상화 단원"이 아니라 "추상화의 한계선을 다루는 단원"이 된다.

| 소단원 | 이 렌즈로 볼 때의 축 |
|---|---|
| **01 문제의 상태** | 무엇을 **남겨야** 문제로 성립하는가 |
| 02 문제의 추상화 | 무엇을 **버려도 되는가**, 버리면 안 되는 선은 어디인가 |
| 03 알고리즘 표현 | 남긴 것을 **어떤 형식으로 적어야** 남이 그대로 실행하는가 |
| 04 알고리즘 분석 | 무엇을 **기준으로 비교해야** 좋고 나쁨을 말할 수 있는가 |

04까지 닿는다 — 알고리즘을 비교할 때 실제 초 단위 시간을 버리고 '비교 횟수'
하나만 남기는 것이 바로 추상화이고, 그것이 이후의 시간복잡도로 이어진다.

## 2. 일반화 문장

**일반화 1 (본체):** 문제를 풀 수 있는 형태로 만들려면 상황에서 결과를 좌우하는
것만 골라 상태로 정의해야 하며, 빠뜨리면 이어갈 수 없고 넘치면 다루기 어려워진다.

**일반화 2:** 문제 해결은 상태를 바꾸어 가는 과정이며, 시작 상태와 목표 상태가
정해져야 무엇을 해야 하는지가 정해진다.

**점검**

- [x] 다른 단원이나 다른 교과에도 통하는가 — 일반화 1은 02(추상화),
  04(비교 기준 고르기), 07(리스트에 무엇을 저장할지), 과학의 '계의 상태',
  수학의 '변수 정하기'에 그대로 통함. 일반화 2는 게임·요리·여행 계획 등
  일상 문제 해결에 통함
- [x] 특정 도구나 프로그램 이름이 들어가 있지 않은가
- [x] "무엇이다"가 아니라 "어떻게/왜 그러한가"를 담고 있는가 —
  둘 다 조건-결과 관계 진술("~해야 하며, 빠뜨리면 ~ 넘치면 ~")

## 3. 탐구 질문

| 종류 | 질문 |
|---|---|
| 사실적 (답이 정해진 것) | 늑대·염소·양배추·농부의 위치 조합은 모두 몇 가지인가? 위치 카드를 3장만 적으면 가능한 상황은 몇 가지가 되는가? |
| 개념적 (일반화로 이끄는 것) | 껐다 켜도 이어서 할 수 있으려면 무엇을 적어두어야 하는가? 적었는데도 가능한 상황 수가 줄지 않는 정보는 다른 정보와 무엇이 다른가? |
| 논쟁적 (정답이 갈리는 것) | 적어둘 정보는 많을수록 안전한가? 전부 적어두면 확실한데, 왜 굳이 줄이려 할까? |

**「어디까지 버려도 되는가」류의 질문은 여기서 다루지 않는다.** 그것은 02의 핵심
질문이다. 01은 일반화 1의 뒷부분("넘치면 다루기 어려워진다")까지만 열어두고,
"버려도 되는 선은 어디인가"는 02가 앱으로 실험하게 남긴다.
논쟁적 질문을 앱의 극단값(카드 9장 전부)과 맞물리게 잡은 이유다.

## 5. 앱이 담당할 것

이 단원의 앱은 **「내일 이어하려면 무엇을 적어야 할까」** 하나다. 한 화면, 조작 하나.
소재는 강 건너기(늑대·염소·양배추·농부)이고, **퍼즐을 푸는 앱이 아니라 판을 적어두는
앱**이다. 배는 화면에 있지만 조작 대상이 아니라 농부를 따라다니는 장식이다 —
미끼 카드 「배의 색깔」이 가리키는 것을 화면에 남기기 위해서다.

**조작 대상:** 정보 카드 9장을 켜고 끄기 — 늑대의 위치 / 염소의 위치 / 양배추의 위치 /
농부의 위치 / 지금까지 건넌 횟수 / 마지막으로 옮긴 것 / 걸린 시간 / 강의 폭 / 배의 색깔.
(강 건너기 판은 학생이 몇 수 두다가 아무 지점에서 멈추면 되는 준비 동작이고,
조작의 중심은 카드다)

**즉시 보이는 변화:** 카드를 켜고 끌 때마다 **"적어둔 것만으로 만들 수 있는 판:
N가지"** 숫자가 즉시 바뀌고, 그 N개의 판이 작은 그림으로 함께 뜬다.
N이 1이 되면 "내일 이어서 할 수 있음", 2 이상이면 "어느 판이었는지 알 수 없음".
미끼 카드(시간·강의 폭·배의 색깔·건넌 횟수·마지막에 옮긴 것)를 켜면 **숫자가
전혀 줄지 않는다** — 이 무반응이 이 앱의 핵심 피드백이다.

**학생이 하는 판단:** N을 1로 만드는 **가장 적은 카드 조합**을 스스로 찾기.
앱은 정답을 판정하지 않고 숫자만 보여준다. 몇 장이 최소인지 알려주지 않으므로
학생이 한 장씩 빼보며 경계를 찾는다.

**극단값:** 카드 0장(16가지 — 아무것도 모름) ↔ 카드 9장 전부(1가지지만 적을 것이
9개). 그리고 미끼 카드만 5장 켠 상태 — 다섯 장이나 적었는데 여전히 16가지.

**앱이 하지 않을 것** (개발 탭에서 임의로 넣지 말 것):
- 규칙 위반(농부 없는 쪽에 늑대·염소, 또는 염소·양배추만 남음) 판정으로 진행을
  막지 않는다. 빨간 테두리 표시만 하고 되돌릴 수 있게 둔다 — 틀린 조작을 허용하는 원칙
- 퍼즐 정답(최소 이동 횟수) 안내, 자동 풀이, 단계 잠금 없음
- '상태', '초기 상태', '목표 상태' 같은 **용어를 앱 화면에 쓰지 않는다.**
  용어는 2차시 정리에서 학생 표현에 이름을 붙이며 처음 등장한다
- 시작 판과 목표 판은 화면 위쪽에 같은 카드 표기로 **표시만** 한다(조작 대상 아님)

## 6. 수업·클래스룸이 담당할 것

| 단계 | 어디서 | 내용 |
|---|---|---|
| 관계 맺기 | 수업 | "게임을 껐다 켜도 이어서 할 수 있는 건 무엇이 저장돼 있기 때문일까?" **구두 발문 + 손들기 4분.** 패들렛을 쓰지 않는다 — 이 기록은 뒤에서 다시 쓰지 않는데, 한 차시에 도구가 셋이 되면 접속에 시간이 다 간다 |
| 조사하기 | 앱 | 위 5번 (카드를 켜고 끄며 가능한 판의 수가 어떻게 변하는지) |
| 패턴 말하기 | 클래스룸(1차시) → 패들렛(2차시) | 1차시는 학습지에 개인 기록("줄어드는 카드와 안 줄어드는 카드는 무엇이 달랐나"). 2차시에 모둠 문장을 패들렛(셸프, 모둠별 칼럼)에 올려 공유 |
| 정리 | 수업 | 패들렛 문장 → 일반화 1로 다듬기. **그다음에** 교과서 93~96쪽 용어(초기 상태·현재 상태·목표 상태, 구조화)를 학생 표현에 붙여주기 |
| 전이 | 수업 | 다른 문제를 상태로 정의해 보기(학급 자리 바꾸기 / 엘리베이터 / 편의점 재고) → 02 예고: "안 적어도 되는 걸 골랐는데, 그럼 아예 문제에서 지워버려도 될까?" |

**도구는 차시당 둘까지.** 1차시 = 앱 + 클래스룸, 2차시 = 패들렛 + 클래스룸.
패들렛을 2차시에만 쓰는 이유는 그때 비로소 기록이 남아야 하기 때문이다
(모둠 문장 → 학급 문장). 도입에서 쓰면 기록은 안 남고 접속 시간만 든다.

**용어를 마지막에 주는 것이 이 단원 설계의 핵심입니다.** 「초기·현재·목표 상태」를
먼저 알려주고 퍼즐에 적용시키면 탐구가 아니라 용어 대입 연습이 됩니다.

**클래스룸 과제 질문** — 앱의 구체적 조작을 지목하는 형태로 씁니다.

1. 카드를 한 장도 고르지 않았을 때 가능한 판은 몇 가지였나요? 위치 카드 4장을
   모두 고르면 몇 가지가 되었나요?
2. 골랐는데도 가능한 판의 수가 **전혀 줄지 않은** 카드가 있었나요? 그 카드들은
   줄어들게 만든 카드와 무엇이 달랐나요?
3. 가능한 판을 1가지로 만드는 **가장 적은 카드 조합**은 무엇이었나요?
   거기서 한 장을 빼면 무슨 일이 일어났나요?
4. 오늘 고른 카드들을 '상태'라고 부릅니다. 게임 세이브 파일에 들어 있어야 할
   것을 같은 방식으로 정해 보세요. 무엇을 넣고 무엇을 뺄 건가요?

게시 시점: 질문 1~3은 1차시 기록용, **질문 4는 2차시에 학급 문장을 만들고
용어를 연결한 뒤**. 질문 4를 먼저 내면 '상태'라는 답을 교사가 준 셈이 됩니다.

## 7. 차시 계획

주당 2시간 편성 기준. III 대단원 전체 21~28차시 안에서 **III-1 네 소단원에 각 2차시
(합 8차시)** 를 배정한다. 남는 압박은 III-2(프로그래밍 실습)에서 조정한다 —
「프로그래밍 시작하기」와 「실생활 문제 해결」이 성취기준 매칭이 가장 느슨하다.

**1차시 — 만져보고 기록하기** (앱, 클래스룸)

| 분 | 활동 |
|---|---|
| 4 | 관계 맺기 — 게임 세이브 발문, 구두 |
| 6 | 앱 접속 + 강 건너기 판을 몇 수 두고 아무 데서나 멈추기 |
| 21 | 카드 실험 — 0장 → 미끼만 5장 → 위치 4장 → 한 장씩 빼며 최소 조합 찾기 |
| 12 | 학습지 기록 (과제 질문 1~3) |
| 2 | 마무리 발문 — "안 줄어든 카드들, 다음 시간에 이야기하자" |

**2차시 — 이름 붙이고 넓히기** (패들렛, 클래스룸, 교과서)

| 분 | 활동 |
|---|---|
| 10 | 모둠별 기록 공유 → 모둠 문장을 패들렛 셸프에 |
| 12 | **학급 일반화 문장 다듬기** — 가장 먼저 지켜야 할 시간 |
| 8 | 교과서 용어 연결 (초기·현재·목표 상태, 구조화) |
| 10 | 전이 — 다른 문제를 상태로 정의(과제 질문 4) + 02 예고 |
| 5 | 여유 |

**12분을 지키는 것이 이 단원의 성패입니다.** 시간이 밀리면 가장 먼저 잘리는 것이
일반화 다듬기이고, 그러면 교사가 "이걸 상태라고 해"라고 불러주게 됩니다.
그 순간 강의식 수업과 결과가 같아지고 앱을 만든 의미가 사라집니다.
밀릴 것 같으면 전이(10분)를 줄이고 과제로 돌립니다.
