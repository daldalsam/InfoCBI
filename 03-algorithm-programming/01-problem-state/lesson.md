# III-1-01 문제의 상태와 구조화 수업 설계

교과서(비상교육) 93~96쪽 / 폴더 `03-algorithm-programming/01-problem-state`

## 1. 개념적 렌즈

**렌즈:** 추상화(abstraction)

**왜 이 렌즈인가:** 교육과정 교과 관통 개념표에서 추상화는 알고리즘과 프로그래밍의
핵심 개념이고, III 영역의 핵심 아이디어가 모두 추상화 위에 서 있다.
II에서 쓴 '표현'을 계속 이어받는 방법도 있었으나, 표현은 04(효율성 비교)에
닿지 않아 III-1 전체를 묶지 못한다. 여기서 렌즈를 갈아타고 '표현'은 03에서
보조 개념으로 재등장시킨다.

**III-1 네 소단원의 일반화 축** — 렌즈 하나 아래 네 축을 미리 갈라둔다.
02의 소단원 제목이 「문제의 추상화」라 렌즈와 겹치는데, 축을 나눠두면
02는 "추상화 단원"이 아니라 "추상화의 한계선을 다루는 단원"이 된다.

| 소단원 | 이 렌즈로 볼 때의 축 |
|---|---|
| **01 문제의 상태** | 무엇을 **남겨야** 문제로 성립하는가 |
| 02 문제의 추상화 | 무엇을 **버려도 되는가**, 버리면 안 되는 선은 어디인가 |
| 03 알고리즘 표현 | 남긴 것을 **어떤 형식으로 적어야** 남이 그대로 실행하는가 |
| 04 알고리즘 분석 | 무엇을 **기준으로 비교해야** 좋고 나쁨을 말할 수 있는가 |

04까지 닿는다 — 알고리즘을 비교할 때 실제 초 단위 시간을 버리고 '비교 횟수'
하나만 남기는 것이 바로 추상화이고, 그것이 이후의 시간복잡도로 이어진다.

**03 설계 때 볼 것 — 강 건너기를 다시 쓴다.** 01이 「판 **하나**를 어떻게 적나」라면
03은 「판들의 **연속**을 어떻게 적나」다. 같은 소재, 다른 질문이라 학생이 소재를
다시 배울 필요가 없고, 교사가 이미 만들어 둔 「상태 변화 기록표」가 거기서
제자리를 찾는다(아래 5번 「기존 앱 재사용」 참고).

## 2. 일반화 문장

**일반화 1 (본체):** 문제를 풀 수 있는 형태로 만들려면 상황에서 결과를 좌우하는
것만 선택해 상태로 정의해야 하며, 빠뜨리면 이어갈 수 없고 넘치면 다루기 어려워진다.

**일반화 2:** 문제 해결은 상태를 바꾸어 가는 과정이며, 시작 상태와 목표 상태가
정해져야 무엇을 해야 하는지가 정해진다.

**점검**

- [x] 다른 단원이나 다른 교과에도 통하는가 — 일반화 1은 02(추상화),
  04(비교 기준 선택하기), 07(리스트에 무엇을 저장할지), 과학의 '계의 상태',
  수학의 '변수 정하기'에 그대로 통함. 일반화 2는 게임·요리·여행 계획 등
  일상 문제 해결에 통함
- [x] 특정 도구나 프로그램 이름이 들어가 있지 않은가
- [x] "무엇이다"가 아니라 "어떻게/왜 그러한가"를 담고 있는가 —
  둘 다 조건-결과 관계 진술("~해야 하며, 빠뜨리면 ~ 넘치면 ~")

## 3. 탐구 질문

| 종류 | 질문 |
|---|---|
| 사실적 (답이 정해진 것) | 농부·늑대·염소·양배추의 위치 조합은 모두 몇 가지인가? 위치 카드를 세 장만 적으면 가능한 판은 몇 가지가 되는가? |
| 개념적 (일반화로 이끄는 것) | 친구가 내 판을 똑같이 만들려면 무엇을 알려주어야 하는가? 적었는데도 가능한 판의 수가 줄지 않는 정보는 다른 정보와 무엇이 다른가? |
| 논쟁적 (정답이 갈리는 것) | 적어둘 정보는 많을수록 안전한가? 전부 적어두면 확실한데, 왜 굳이 줄이려 할까? |

**「어디까지 버려도 되는가」류의 질문은 여기서 다루지 않는다.** 그것은 02의 핵심
질문이다. 01은 일반화 1의 뒷부분("넘치면 다루기 어려워진다")까지만 열어두고,
"버려도 되는 선은 어디인가"는 02가 앱으로 실험하게 남긴다.
논쟁적 질문을 앱의 극단값(카드 9장 전부)과 맞물리게 잡은 이유다.

## 5. 앱이 담당할 것

이 단원의 앱은 **「다음에 이어서 하려면 무엇을 적어야 할까?」** 하나다.
소재는 교과서 93~96쪽의 강 건너기(**농부·늑대·염소·양배추**)이고,
**퍼즐을 푸는 앱이 아니라 판을 적어두는 앱**이다.

### 활동의 틀 — 학생은 「출제자」다

> "다 풀었지? 이제 친구한테 문제를 내주자. 처음부터 말고 **네가 어려웠던 그 지점**부터
> 시작하게 해주고 싶어. 친구가 그 판을 똑같이 만들 수 있게 **무엇을 알려줄래?**"

「내가 이어하려고 적는다」가 아니라 「친구에게 낼 문제를 적는다」로 잡은 이유:

- **빨리 푸는 학생이 손해 보지 않는다.** 퍼즐을 완전히 이해한 학생만 "어디가
  어려운지"를 안다. 다 푼 학생은 남는 시간을 좋은 문제를 선택하는 데 쓴다
- **못 푼 학생도 그대로 넘어간다.** "다 못 풀었으면 지금 판을 내면 돼."
  어느 판이든 16 → 8 → 2 → 1로 똑같이 진행되므로 기다릴 필요가 없다
- **정확성에 책임이 생긴다.** 출제자는 틀리면 안 된다. 대충 적어서 친구가 딴 판을
  만들면 그것이 실패로 느껴진다

### 조작 대상

**정보 카드 아홉 장을 선택하고 해제하기.** 세 종류가 섞여 있다.

| 종류 | 카드 | 선택하면 |
|---|---|---|
| **필요** (4) | 농부의 위치 / 늑대의 위치 / 염소의 위치 / 양배추의 위치 | 후보가 절반으로 |
| **중복** (1) | **배의 위치** | 농부를 이미 선택했다면 **안 줄어듦** |
| **무관** (4) | 지금까지 건넌 횟수 / 마지막에 옮긴 것 / 걸린 시간 / 배의 색깔 | 언제나 **안 줄어듦** |

강 건너기 판(대상을 배에 태우고 건너기)은 앞단의 준비 동작이고, 조작의 중심은 카드다.

### 즉시 보이는 변화

카드 선택을 바꿀 때마다 **"적어둔 것만으로 만들 수 있는 판: N가지"** 숫자가 즉시
바뀌고, 그 N개의 판이 작은 그림으로 함께 뜬다. N이 1이면 「친구가 이 판을 정확히
받는다」, 2 이상이면 「친구는 어느 판인지 모른다」.

| 선택한 카드 | N |
|---|---|
| 없음 | 16 |
| 무관 카드 넉 장 전부 | **16** (넉 장이나 적었는데 그대로) |
| 농부만 | 8 |
| 배만 | 8 |
| **농부 + 배** | **8** (둘이 같은 정보였다) |
| 늑대 + 염소 + 양배추 | 2 |
| 늑대 + 염소 + 양배추 + 농부 | **1** |
| 늑대 + 염소 + 양배추 + 배 | **1** |
| 아홉 장 전부 | 1 (되지만 아홉 개를 적었다) |

### 학생이 하는 판단

**N을 1로 만드는 가장 적은 카드 조합을 스스로 찾기.** 앱은 정답을 판정하지 않고
숫자만 보여준다. 최소가 몇 장인지 알려주지 않으므로 학생이 한 장씩 빼보며
경계를 찾는다.

**최소 조합이 두 가지다**(…+농부 / …+배). 모둠마다 답이 다르게 나오고 둘 다 맞다.
"왜 둘 다 되지?"에서 중복 정보의 발견이 일어난다.

### 극단값

카드 0장(16가지 — 아무것도 모름) ↔ 아홉 장 전부(1가지지만 적을 것이 아홉 개).
그리고 무관 카드만 넉 장 선택한 상태 — 넉 장이나 적었는데 여전히 16가지.
농부와 배를 같이 선택한 상태 — 상관있는 정보인데도 숫자가 안 움직인다.

### 앱이 하지 않을 것 (개발 탭에서 임의로 넣지 말 것)

- 규칙 위반(농부 없는 쪽에 늑대+염소, 염소+양배추) 판정으로 **진행을 막지 않는다.**
  표시만 하고 되돌릴 수 있게 둔다 — 틀린 조작을 허용하는 원칙
- 퍼즐 정답(최소 이동 횟수) 안내, 자동 풀이, 단계 잠금 없음
- **「상태 변화 기록표」를 넣지 않는다.** 이 앱의 핵심 발견이 "지나온 이력은 상태가
  아니다"인데, 단계 기록표가 화면에 크게 있으면 학생은 "저건 중요한 것"으로 읽는다.
  그 표는 03에서 제자리를 찾는다
- **'상태', '초기 상태', '목표 상태', '구조화' 같은 용어를 앱 화면에 쓰지 않는다.**
  용어는 2차시 정리에서 학생 표현에 이름을 붙이며 처음 등장한다
- 성취기준 번호, 교과서 쪽수, 개념 설명 카드를 화면에 두지 않는다
- 시작 판과 목표 판은 화면 위쪽에 **표시만** 한다(조작 대상 아님)

### 기존 앱 재사용

교사가 전에 만든 강 건너기 앱(제미나이 작업물, 별도 보관)이 있다. 코드 탭에 첨부해
참고한다. 권리는 만든 사람에게 있고, 가져오는 부분은 문제 자체의 표준 표현이다.

| | 내용 |
|---|---|
| **가져올 것** | 상태 모델 `{farmer, wolf, goat, cabbage, boatSide}` — 새 앱의 뼈대 그대로 / 규칙 검사 로직(배에 탄 채로는 잡아먹히지 않음, 농부가 배에 있으면 배가 있는 쪽으로 간주 — 경계 조건이 정확함) / 캐릭터 탭 → 배 탭 이동 조작 / 이모지 / 되돌리기 |
| **두고 갈 것** | Tailwind CDN(프로젝트 기술 스택 위반 — CSS를 새로 씀) / 학번·이름 입력(개인정보 원칙) / 퀴즈·점수·리포트(평가는 클래스룸) / 성취기준·교과서 쪽수 표시 / 개념 설명 카드 / 상태 변화 기록표 |

## 6. 수업·클래스룸이 담당할 것

| 단계 | 어디서 | 내용 |
|---|---|---|
| 관계 맺기 | 수업 | "게임을 껐다 켜도 이어서 할 수 있는 건 무엇이 저장돼 있기 때문일까?" **구두 발문 + 손들기 4분.** 패들렛을 쓰지 않는다 — 이 기록은 뒤에서 다시 쓰지 않는데, 한 차시에 도구가 셋이 되면 접속에 시간이 다 간다 |
| 조사하기 | 앱 | 위 5번 (퍼즐을 풀고 → 친구에게 낼 판을 놓고 → 카드로 적기) |
| 패턴 말하기 | 클래스룸(1차시) → 패들렛(2차시) | 1차시는 학습지에 개인 기록. 2차시에 모둠 문장을 패들렛(셸프, 모둠별 칼럼)에 올려 공유 |
| 정리 | 수업 | 패들렛 문장 → 일반화 1로 다듬기. **그다음에** 교과서 93~96쪽 용어(초기 상태·현재 상태·목표 상태, 구조화)를 학생 표현에 붙여주기 |
| 전이 | 수업 | 다른 문제를 상태로 정의해 보기(학급 자리 바꾸기 / 엘리베이터 / 편의점 재고) → 02 예고: "안 적어도 되는 걸 알아냈는데, 그럼 아예 문제에서 지워버려도 될까?" |

**도구는 차시당 둘까지.** 1차시 = 앱 + 클래스룸, 2차시 = 패들렛 + 클래스룸.
패들렛을 2차시에만 쓰는 이유는 그때 비로소 기록이 남아야 하기 때문이다
(모둠 문장 → 학급 문장).

**클래스룸 과제 질문** — 앱의 구체적 조작을 지목하는 형태로 씁니다.
숫자·이름 기록은 학습지의 활동 1~3이 맡고, **질문은 해석만** 맡습니다
(같은 것을 두 번 쓰게 하지 않는다).

1. 활동 1에서 넉 장을 선택했는데도 16가지 그대로인 경우와, 똑같이 넉 장으로
   1가지까지 줄어드는 경우가 있었습니다. 장수는 같은데 왜 결과가 달랐을까요?
2. 숫자를 전혀 줄이지 못한 카드들은 서로 무엇이 닮았나요? 줄어들게 만든
   카드들과는 무엇이 달랐나요?
3. 활동 2에서 농부의 위치와 배의 위치를 **둘 다** 선택해도 숫자는 8에서
   움직이지 않았습니다. 왜 그럴까요?
4. 활동 3에서 한 장만 빼도 가능한 판이 늘어났습니다. 내 조합만 받은 친구가
   내 판을 **정확히** 만들 수 있는 까닭은 무엇일까요?
5. 오늘 선택한 카드들을 '상태'라고 부릅니다. 게임 세이브 파일에 들어 있어야 할
   것을 같은 방식으로 정해 보세요. 무엇을 넣고 무엇을 뺄 건가요?

게시 시점: 질문 1~4는 1차시 기록용, **질문 5는 2차시에 학급 문장을 만들고
용어를 연결한 뒤**. 질문 5를 먼저 내면 '상태'라는 답을 교사가 준 셈이 됩니다.
모둠 간 **조합 비교**(같았나 달랐나)는 과제가 아니라 2차시 첫 10분의 수업
활동입니다 — 1차시 학습지의 「(다음 시간)」 칸에 적습니다.

## 7. 차시 계획

### 7.1 1차시 — 만져보고 기록하기

**수업 흐름:** 관계 맺기 → 퍼즐 → 출제 → 카드 실험

**준비물:** 학생 기기, 앱 주소, 질문 1~4 학습지. 이 차시에는 패들렛을
사용하지 않는다.

| 시간 | 단계 | 교사가 하는 일 |
|---|---|---|
| 0~4분 | 관계 맺기 | “게임을 껐다가 다시 켜도 이어서 할 수 있지? 무엇이 저장돼 있기 때문일까?”라고 묻고 두세 명의 답을 듣는다. 아직 정답을 정리하지 않는다. |
| 4~6분 | 앱 접속 | 클래스룸에 게시한 주소로 앱을 연다. 시작·목표 그림과 건너가기 버튼만 확인하고 바로 활동한다. |
| 6~14분 | 퍼즐 풀기 | 네 대상을 오른쪽 기슭으로 옮겨 보게 한다. 학생이 조작하며 이동 규칙을 찾도록 하고, 다 풀지 못해도 다음 활동으로 갈 수 있음을 안내한다. |
| 14~17분 | 출제로 전환 | 친구가 이어서 풀 판을 하나 고르게 한다. 다 푼 학생은 어려웠던 지점, 다 풀지 못한 학생은 현재 판을 사용한다. 이때 학습지를 배부하고 선택한 판을 기록하게 한다. |
| 17~41분 | 카드 실험 | ① 카드가 없을 때의 수 확인 ② 수가 줄지 않는 카드 네 장 찾기 ③ 네 대상의 위치 카드 선택 ④ 농부와 배를 각각 또는 함께 선택해 비교 ⑤ 가능한 판을 하나로 만드는 최소 조합 찾기를 차례로 수행한다. 결과는 학습지 활동 1~3에 기록하고 질문 1~4와 한 문장 도전을 작성한다. |
| 41~45분 | 마무리 | 친구에게 보이는 가능한 판을 함께 보고, 선택한 카드가 후보를 줄였다는 점을 확인한다. 개념 용어는 다음 시간에 붙일 것임을 안내한다. |

**카드 실험에서 사용할 발문**

- “넉 장이나 적었는데 왜 그대로 16이야?”
- “농부랑 배를 둘 다 선택했는데 숫자가 왜 안 움직일까?”
- “거기서 한 장 빼 볼래? 무슨 일이 생겨?”

**예상 반응과 대응**

- 카드 수의 정답을 물으면 한 장씩 빼 보며 직접 찾는 활동임을 안내한다.
- 건넌 횟수 카드가 수를 줄이지 못하는 이유는, 그 정보만으로 현재 판을 그릴
  수 있는지 되묻는다.
- 홀수 이동 횟수로 배의 위치를 알 수 있다는 의견은 타당한 생각으로 인정하고
  2차시 토론에서 다시 다룬다.
- 농부 카드와 배 카드로 최소 조합이 갈리면 둘 다 맞을 수 있음을 확인하고
  그 이유를 묻는다.

**클래스룸 과제**

1차시 시작 전에 게시하고 `[앱 주소]`를 실제 주소로 바꾼다.

> **[알고리즘 01-1차시] 다음에 이어서 하려면 무엇을 적어야 할까? — 발견 기록**
>
> 오늘 수업에서 조작한 앱을 근거로 답합니다. 앱: [앱 주소]
>
> 숫자는 학습지 활동 칸에 이미 적었습니다. 여기서는 그 숫자가 왜 그렇게
> 나왔는지 여러분의 생각을 쓰세요.
>
> 1. 넉 장을 골랐는데도 16가지인 경우와 넉 장으로 1가지가 된 경우는 왜
>    결과가 달랐나요?
> 2. 숫자를 줄이지 못한 카드들은 무엇이 닮았고, 줄어들게 만든 카드들과는
>    무엇이 달랐나요?
> 3. 농부의 위치와 배의 위치를 함께 선택해도 숫자가 8에서 줄지 않은 이유는
>    무엇인가요?
> 4. 최소 조합만 받은 친구가 내가 고른 판을 정확히 만들 수 있는 이유는
>    무엇인가요?

### 7.2 2차시 — 이름 붙이고 넓히기

**수업 흐름:** 기록 비교 → 일반화 → 용어 연결 → 다른 문제에 적용

**준비물:** 1차시 학습지, 모둠 문장용 패들렛, 2차시 학습지, 교과서,
질문 5 과제

| 시간 | 단계 | 교사가 하는 일 |
|---|---|---|
| 0~10분 | 기록 비교하기 | 모둠별로 최소 카드 조합을 비교한다. “___만 적으면 친구가 똑같이 만들 수 있다”라는 문장으로 공통점을 정리해 패들렛에 올린다. |
| 10~22분 | 일반화 다듬기 | 모둠 문장의 공통점을 찾아 학급 문장으로 정리한다. 아홉 장을 모두 적는 방법의 불편과 농부·배 두 조합이 모두 가능한 이유를 질문한다. 완성 문장은 패들렛에 고정한다. |
| 22~30분 | 용어 연결 | 2차시 학습지를 배부하고 학급 문장을 옮겨 적게 한다. 앱의 카드 묶음과 장면을 상태, 초기 상태, 현재 상태, 목표 상태, 구조화라는 교과서 용어에 연결한다. 게임 저장에 필요한 정보가 무엇인지 다시 묻는다. |
| 30~40분 | 다른 문제에 적용하기 | 자리 바꾸기, 엘리베이터, 편의점 재고 가운데 하나를 골라 다음에 이어서 해결하려면 필요한 정보를 정한다. 질문 5를 게시하고, 다음 시간에는 불필요한 정보를 문제에서 지워도 되는지 살펴볼 것임을 예고한다. |
| 40~45분 | 여유 | 앞 활동을 마무리한다. 시간이 남으면 학급 문장을 함께 읽고 질문 5 작성을 시작한다. |

**예상 반응과 대응**

- 모둠 문장이 강 건너기 사례에만 머물면 게임 저장에도 통하는 문장으로
  넓혀 보게 한다.
- ‘상태’라는 용어를 먼저 말한 학생의 의견은 기록하고 용어 연결 단계에서
  다시 다룬다.
- 불필요한 카드를 문제에서 지워도 되는지 묻는 학생에게는 다음 단원에서
  확인할 질문이라고 안내한다.

**클래스룸 과제**
