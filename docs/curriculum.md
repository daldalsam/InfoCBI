## 이 문서의 사용법

- `lesson.md`를 작성할 때 **핵심 아이디어**를 일반화 문장의 출발점으로 씁니다.
- 앱 적합도는 참고용입니다. 실제 개발 순서는 `docs/textbook.md`를 따릅니다.
- 성취기준 문장은 고치지 않습니다. 해설과 앱 아이디어는 수업하면서 다듬습니다.

**앱 적합도 표기**

| 표기 | 뜻 |

| ○ | 앱으로 일부 가능. 보조 도구 수준 |
| △ | 조사·토론·프로젝트가 나음. 앱은 자료 제시용 정도 |

# 핵심 아이디어 = 일반화 문장의 출발점

교육과정 일러두기는 핵심 아이디어를 이렇게 정의합니다.

> 영역을 아우르면서 해당 영역의 학습을 통해 **일반화할 수 있는** 내용을 핵심적으로
> 진술한 것. 이는 해당 영역 학습의 초점을 부여하여 깊이 있는 학습을 가능하게 하는
> 토대가 됨.

개념기반탐구에서 말하는 일반화와 성격이 같습니다. `lesson.md`의 일반화 문장은
**핵심 아이디어를 그대로 쓰거나, 학생 수준으로 다듬어서** 쓰면 됩니다.

# (1) 컴퓨팅 시스템

## 핵심 아이디어

- 하드웨어와 소프트웨어의 유기적 연결을 통해 동작하는 컴퓨팅 시스템은 사회적,
  기술적 가치를 높이는 데 활용된다.
- 컴퓨팅 시스템을 설계하는 것은 시스템에 대한 전체 흐름과 자원 할당의 가치를
  이해하는 데 도움을 준다.

## 내용 요소

| 범주 | 내용 |
|---|---|
| 지식·이해 | 컴퓨팅 시스템의 동작 원리 / 운영 체제의 기능 / 피지컬 컴퓨팅의 개념 |
| 과정·기능 | 구성요소를 파악하고 동작 원리를 운영 체제와 관계짓기 / 피지컬 컴퓨팅 적용 사례 조사하기 / 피지컬 컴퓨팅 시스템 구성하기 |
| 가치·태도 | 컴퓨팅 시스템의 필요성과 가치를 판단하는 자세 / 구성요소를 목적에 맞게 선택하는 유연한 태도 |

## 성취기준

### [9정01-01] 컴퓨팅 시스템의 구성요소와 동작 원리를 이해하고, 운영 체제의 기능을 분석한다.

- **핵심 개념**: 관계, 자원 할당
- **해설 요지**: 컴퓨팅 시스템이 컴퓨터를 넘어 확장되었음을 인식한다. 운영 체제가
  시스템을 효율적으로 활용하기 위해 수행하는 작업을 설명할 수 있어야 한다.
- **학생이 할 수 있어야 하는 것**: 구성요소를 파악하기 / 동작 원리를 운영 체제와
  관계짓기 / 운영 체제의 작업을 설명하기
- **앱 아이디어** ◎: 자원 할당 시뮬레이터. 프로그램을 여러 개 실행하고 CPU와
  메모리를 학생이 직접 배분해본다. 잘못 배분하면 느려지거나 멈추는 것을 눈으로 확인.
  → 발견할 것: 자원은 유한하고, 운영 체제가 이를 조정한다

### [9정01-02] 피지컬 컴퓨팅의 개념을 이해하고, 생활 속에서 적용된 사례 조사를 통해 컴퓨팅 시스템의 필요성과 가치를 판단한다.

- **핵심 개념**: 가치 판단
- **해설 요지**: 구성요소가 고유한 역할을 담당함을 이해하고, 사회의 다양한 영역에서
  피지컬 컴퓨팅이 유용하게 쓰일 수 있음을 판단한다.
- **학생이 할 수 있어야 하는 것**: 사례 조사하기 / 필요성과 가치를 판단하기
- **앱 아이디어** △: 조사와 판단이 중심이라 앱보다 클래스룸 과제가 적합.
  굳이 만든다면 사례를 입력하면 입력·처리·출력 구조로 분해해 보여주는 도구.

### [9정01-03] 문제 해결 목적에 맞는 피지컬 컴퓨팅 구성요소를 선택하여 시스템을 구상한다.

- **핵심 개념**: 목적과 선택
- **학생이 할 수 있어야 하는 것**: 목적에 맞게 센서와 출력 장치를 고르기 /
  시스템을 구상하기
- **앱 아이디어** ○: 가상 피지컬 컴퓨팅 구성기. 센서와 출력 장치 목록에서 골라
  연결하면 "이 조합으로 무엇이 가능한지" 보여준다.
  **실물 기기로 만드는 활동이 본체이고, 앱은 기기가 부족하거나 사전 구상이 필요할 때
  쓰는 보조 도구입니다.**
  → 발견할 것: 같은 목적에도 여러 조합이 가능하고, 조합마다 장단점이 있다

# (2) 데이터

## 핵심 아이디어

- 데이터를 관리하기 위해서는 아날로그 데이터를 컴퓨터에서 처리할 수 있는 디지털
  형태로 변환하는 과정이 필요하다.
- 문제 해결을 위해서는 필요한 데이터를 수집하고, 분석하여 의미를 해석하는 것이
  필요하다.
- 수집된 데이터 간의 관계를 파악하고, 구조화하는 것은 데이터를 통해 새로운 지식을
  찾는 데 도움을 준다.

## 내용 요소

| 범주 | 내용 |
|---|---|
| 지식·이해 | 디지털 데이터 표현 방법 / 데이터 수집과 관리 / 데이터 구조화 및 해석 |
| 과정·기능 | 데이터를 목적에 맞게 수집·분류·저장하기 / 데이터를 구조화하고 의미 해석하기 |
| 가치·태도 | 디지털 변환의 긍정적 측면 인식 / 데이터에 기반하여 현상을 바라보는 관점 |

## 성취기준

### [9정02-01] 실생활의 데이터가 디지털 형태로 변환되어 활용되는 긍정적 가치를 탐색하고, 다양한 데이터를 디지털 형태로 표현한다.

- **핵심 개념**: 표현, 이산화
- **해설 요지**: 디지털 데이터의 특징과 장점을 탐색하고, 문자·이미지·소리·동영상을
  컴퓨팅 시스템에서 표현하는 기법을 활용해 실제로 표현할 수 있어야 한다.
- **학생이 할 수 있어야 하는 것**: 디지털 변환의 가치 설명하기 / 문자·이미지·소리를
  실제로 디지털로 표현하기
- **앱 아이디어** ◎ **(첫 앱으로 가장 추천)**:
  - 픽셀 격자를 켜고 끄며 그림 만들기
  - 비트 수 슬라이더(1~8)로 색 개수와 파일 크기가 함께 변하는 것 확인
  - 소리 파형을 샘플링 간격에 따라 다르게 표현
  - 문자를 코드값으로 변환
  → 발견할 것: 연속적인 것을 잘게 나눌수록 원본에 가깝지만 저장 공간이 늘어난다

### [9정02-02] 문제 해결에 적합한 데이터를 수집하고, 목적에 맞게 구분하여 관리한다.

- **핵심 개념**: 분류, 목적
- **해설 요지**: 데이터의 종류·의미·공통점 등 형식에 따라 구분하여 저장하고 활용한다.
- **학생이 할 수 있어야 하는 것**: 목적에 맞는 데이터 고르기 / 기준을 세워 분류하기
- **앱 아이디어** ○: 분류 기준 실험 도구. 같은 데이터 묶음을 여러 기준으로 나눠보고
  결과가 어떻게 달라지는지 비교.
  → 발견할 것: 분류 기준은 목적에 따라 달라진다

### [9정02-03] 실생활의 데이터를 표, 다이어그램 등 다양한 형태로 구조화한다.

- **핵심 개념**: 구조화
- **학생이 할 수 있어야 하는 것**: 같은 데이터를 여러 형태로 나타내기
- **앱 아이디어** ○: 같은 데이터를 표·막대·원·트리 등으로 즉시 바꿔 보여주는 도구.
  → 발견할 것: 나타내는 형태에 따라 보이는 것이 달라진다

### [9정02-04] 사례를 중심으로 데이터 간의 관계를 파악하고, 데이터에 기반하여 의미를 해석한다.

- **핵심 개념**: 관계, 해석
- **해설 요지**: 분석하기 용이한 형태로 나타내고, 결과의 가치를 인식하며, 데이터를
  기반으로 자신의 주장을 논리적으로 설명할 수 있어야 한다.
- **학생이 할 수 있어야 하는 것**: 관계 찾기 / 근거를 들어 주장하기
- **앱 아이디어** ○: 두 변수의 관계를 흩어진 점으로 보여주고 학생이 추세를 그어보게
  하는 도구. 상관과 인과를 혼동하는 사례도 함께.
  → 발견할 것: 관계가 있어 보인다고 원인은 아니다

### [9정02-05] 여러 학문 분야의 사례를 중심으로 데이터를 수집·분석하여 융합적으로 문제를 해결한다.

- **핵심 개념**: 전이, 융합
- **학생이 할 수 있어야 하는 것**: 다른 교과 맥락에 데이터 분석 적용하기
- **앱 아이디어** △: 프로젝트 성격이라 앱보다 클래스룸 과제가 적합.

# (3) 알고리즘과 프로그래밍

## 핵심 아이디어

- 알고리즘은 다양한 설계 전략을 통해 일상생활의 문제를 해결하는 데 활용된다.
- 자동화를 고려해 설계된 알고리즘은 컴퓨터가 이해할 수 있는 언어로 구현되어 생활을
  더욱 편리하게 하는 데 활용된다.
- 프로그램 개발은 협력이 필요하며, 공유하는 문화를 통해 더 좋은 프로그램이 개발된다.

## 내용 요소

| 범주 | 내용 |
|---|---|
| 지식·이해 | 문제 추상화 / 알고리즘 표현 방법 / 순차적인 데이터 저장 / 논리 연산 / 중첩 제어 구조 / 함수와 디버깅 |
| 과정·기능 | 문제의 초기·현재·목표 상태를 정의하고 구조화하기 / 다양한 알고리즘을 설계하고 적용하기 / 논리 연산·중첩 제어 구조·순차적 데이터 저장을 활용해 프로그램 작성하기 / 함수로 모듈화하고 오류를 발견해 수정하기 |
| 가치·태도 | 추상화의 중요성 이해 / 다양한 해법 탐색 / 협력과 공유의 가치 / 오류를 해결하려는 자세 |

## 성취기준

### [9정03-01] 문제의 상태를 정의하고 수행 가능한 형태로 구조화한다.

- **핵심 개념**: 추상화, 상태
- **학생이 할 수 있어야 하는 것**: 초기·현재·목표 상태 정의하기
- **앱 아이디어** ○: 퍼즐(물 붓기, 강 건너기 등)의 상태를 학생이 직접 표로 정의하게
  하고, 정의가 맞으면 자동으로 진행되는 도구.
  → 발견할 것: 문제를 풀기 전에 상태를 정의해야 한다

### [9정03-02] 문제 해결을 위한 추상화의 중요성을 이해하고, 핵심요소를 중심으로 알고리즘을 표현한다.

- **핵심 개념**: 추상화
- **학생이 할 수 있어야 하는 것**: 불필요한 정보 걷어내기 / 핵심요소로 표현하기
- **앱 아이디어** ◎: 정보 걷어내기 실험. 복잡한 지도나 상황에서 요소를 하나씩 지우며
  "언제까지 문제를 풀 수 있는가"를 확인. 너무 지우면 못 풀게 됨.
  → 발견할 것: 추상화는 버리는 것이지만 아무거나 버리면 안 된다

### [9정03-03] 알고리즘의 중요성을 이해하고, 문제를 해결하는 다양한 알고리즘을 비교·분석한다.

- **핵심 개념**: 효율성, 비교
- **해설 요지**: 정보 과목이 추구하는 것은 효과적이고 효율적인 알고리즘임을 인식하고,
  여러 알고리즘의 장단점을 비교·분석하여 논리적으로 설명할 수 있어야 한다.
- **학생이 할 수 있어야 하는 것**: 장단점 비교하기 / 근거를 들어 설명하기
- **앱 아이디어** ◎: 정렬·탐색 알고리즘 나란히 실행. 데이터 개수를 슬라이더로 늘리며
  비교 횟수가 어떻게 벌어지는지 확인. 데이터가 적을 때는 차이가 없다는 것도 중요.
  → 발견할 것: 좋은 알고리즘은 상황에 따라 다르고, 차이는 규모가 커질 때 드러난다

### [9정03-04] 사례를 중심으로 문제 해결에 적합한 전략을 선택하여 알고리즘을 설계한다.

- **핵심 개념**: 전략, 선택
- **학생이 할 수 있어야 하는 것**: 문제에 맞는 전략 고르기
- **앱 아이디어** ○: 같은 문제에 여러 전략을 적용해보고 결과를 비교하는 도구.

### [9정03-05] 데이터를 순차적으로 저장할 수 있는 구조를 활용하여 문제 해결 프로그램을 작성한다.

- **핵심 개념**: 구조, 순차
- **해설 요지**: 입력을 처리해 결과를 도출하는 형태로 프로그램이 제작됨을 이해하고,
  배열이나 리스트를 활용해 많은 양의 데이터를 효과적으로 처리할 수 있어야 한다.
- **학생이 할 수 있어야 하는 것**: 배열·리스트로 데이터 다루기
- **앱 아이디어** ◎: 배열 시각화 도구. 칸이 늘어서 있고 값을 넣고 빼고 찾는 과정이
  애니메이션으로 보임. 인덱스가 0부터인 이유도 함께 확인.
  → 발견할 것: 순서가 있는 저장 구조는 위치로 찾을 수 있어 빠르다

### [9정03-06] 논리 연산과 중첩 제어 구조를 활용하여 문제를 해결하는 프로그램을 작성한다.

- **핵심 개념**: 논리, 제어
- **학생이 할 수 있어야 하는 것**: AND·OR·NOT 조합하기 / 반복 안의 반복 이해하기
- **앱 아이디어** ◎: 논리 연산 실험판. 스위치를 켜고 끄면 결과가 즉시 바뀌고 진리표가
  함께 채워진다. 중첩 반복은 격자를 채워가는 애니메이션으로.
  → 발견할 것: 조건을 조합하는 방식에 따라 결과가 완전히 달라진다

### [9정03-07] 프로그램 작성에서 함수를 활용하고, 프로그램 수행 결과를 디버거로 분석하여 오류를 수정한다.

- **핵심 개념**: 모듈화, 오류
- **학생이 할 수 있어야 하는 것**: 반복되는 부분을 함수로 묶기 / 오류 찾아 고치기
- **앱 아이디어** ○: 같은 동작을 함수 없이/있게 작성한 코드를 나란히 보여주고,
  요구사항이 바뀔 때 어느 쪽이 고치기 쉬운지 체험.
  → 발견할 것: 함수는 지금이 아니라 나중에 고칠 때 값어치가 나온다

### [9정03-08] 실생활의 문제를 탐색하여 발견하고, 프로그래밍을 통해 해결한다.

- **앱 아이디어** △: 프로젝트 성격. 실제 프로그래밍 환경에서 진행.

### [9정03-09] 다양한 학문 분야의 문제 해결을 위해 협력하여 소프트웨어를 개발한다.

- **앱 아이디어** △: 협업 프로젝트. 클래스룸으로 진행 관리.

# (4) 인공지능

## 핵심 아이디어

- 인공지능 기술로 구현된 에이전트는 외부와의 상호 작용을 통해 기존에 해결할 수 없었던
  복잡하고 어려운 문제를 해결하는 데 활용된다.
- 인공지능은 데이터를 기반으로 문제 해결을 가능하게 하므로, 인공지능에 사용되는
  데이터는 윤리적 편향성이 없도록 하는 것이 중요하다.

## 내용 요소

| 범주 | 내용 |
|---|---|
| 지식·이해 | 인공지능의 개념과 특성 / 인공지능 시스템 |
| 과정·기능 | 인공지능 소프트웨어 구별하기 / 학습에 필요한 데이터를 수집하여 활용하기 / 해결할 수 있는 문제 발견하기 / 시스템을 선택하여 문제 해결하기 |
| 가치·태도 | 적용 가능한 문제를 발견하는 자세 / 데이터로 인한 문제 가능성을 최소화하는 태도 |

## 성취기준

### [9정04-01] 인공지능의 개념과 특성을 설명하고 인공지능 소프트웨어를 구별한다.

- **핵심 개념**: 학습, 규칙
- **해설 요지**: 모델·학습·데이터 등 인공지능 시스템이 구성되는 원리와 문제를 해결하는
  과정을 설명할 수 있어야 한다.
- **앱 아이디어** ○: 같은 기능을 규칙 기반과 학습 기반으로 각각 구현해 나란히 비교.
  예외 상황을 넣어보면 차이가 드러난다.
  → 발견할 것: 규칙으로 짠 것과 데이터로 배운 것은 다르게 실패한다

### [9정04-02] 인공지능 학습에서 데이터의 중요성을 이해하고, 학습에 필요한 데이터를 수집하여 분류한다.

- **핵심 개념**: 데이터, 편향
- **앱 아이디어** ◎: 편향 실험기. 학생이 학습 데이터를 직접 고르면 그 결과가 바로
  달라진다. 한쪽으로 치우친 데이터를 넣으면 결과도 치우친다.
  → 발견할 것: 인공지능의 판단은 넣은 데이터를 닮는다

### [9정04-03] 다양한 데이터를 활용하여 인공지능 시스템을 구성하고 적용한다.

- **해설 요지**: 이미지·소리·글자 데이터로 시스템을 학습시키고 활용할 수 있어야 한다.
- **앱 아이디어** ○: 외부 도구(티처블 머신 등)와 병행. 자체 앱은 학습 과정을 단순화해
  보여주는 정도.

### [9정04-04] 인공지능 시스템으로 해결 가능한 문제를 발견하고, 문제 해결에 적합한 인공지능 시스템을 적용한다.

- **앱 아이디어** △: 문제 발견이 중심. 클래스룸 과제가 적합.

### [9정04-05] 인공지능 학습에 필요한 데이터의 수집과 활용에서 발생하는 윤리적인 문제의 해결 방안을 구상한다.

- **해설 요지**: 법적·사회적·윤리적으로 타당한 해결 방안을 제시하고, 여러 측면을
  고려해 장단점을 정리한 후 결론을 도출하는 과정을 경험해야 한다.
- **앱 아이디어** △: 토론이 중심. 앱은 사례 제시용 정도.

# (5) 디지털 문화

## 핵심 아이디어

- 디지털 기술의 발전에 따라 디지털 사회에서 지켜야 할 규칙과 주의해야 할 위험 요소가
  새롭게 등장한다.
- 디지털 세상에서의 직업이나 진로는 기술의 발전에 따라 변화되므로, 기술과 사회 변화의
  관계를 파악하는 것이 중요하다.

## 내용 요소

| 범주 | 내용 |
|---|---|
| 지식·이해 | 디지털 사회와 직업 / 디지털 윤리 / 개인 정보와 저작권 |
| 과정·기능 | 직업의 변화 탐구하기 / 디지털 윤리 토론하기 / 나와 다른 사람을 보호하는 방법 탐구하기 |
| 가치·태도 | 진로 결정에 미치는 영향력을 탐색하는 자세 / 함께 살아가기 위한 윤리적 태도 |

## 성취기준

### [9정05-01] 디지털 사회의 특성을 탐구하고, 사회 변화에 따른 직업의 변화를 탐구한다.

- **앱 아이디어** △: 조사·탐구 중심. 클래스룸이 적합.

### [9정05-02] 디지털 사회의 구성원으로서 편리하고 안전한 생활을 위한 규칙에 대해 민주적으로 논의하고 실천 방안을 수립한다.

- **해설 요지**: 정보 윤리, 사이버 폭력 및 범죄 예방 소양을 갖추고 스마트폰 중독,
  인터넷 중독, 게임 과몰입 등 구체적 사례를 분석할 수 있어야 한다.
- **앱 아이디어** △: 민주적 논의가 핵심. 앱으로 대체하면 취지가 훼손됨.

### [9정05-03] 사례를 중심으로 디지털 공간에서 함께 살아가기 위해 개인 정보 및 권리와 저작권을 보호하는 실천 방법을 탐구한다.

- **핵심 개념**: 권리, 보호
- **앱 아이디어** ○: 사례 판단 도구. 상황을 주고 학생이 "괜찮다/문제다"를 고른 뒤
  판단 근거를 확인. 애매한 사례를 일부러 섞는다.
  → 발견할 것: 저작권과 개인정보는 명확한 선이 아니라 판단이 필요한 영역이다

# 교수·학습 및 평가 (참고)

교육과정이 권장하는 교수·학습 방법: 문제기반학습, 프로젝트 기반학습, 디자인기반학습,
짝 프로그래밍, 탐구학습.

평가 관련 유의점:

- 지식·이해뿐 아니라 과정·기능, 가치·태도를 다면적으로 반영하고 과정을 중시한다.
- 평가 루브릭을 학생과 함께 구성하는 과정을 제공한다.
- 단순·지엽적 지식 평가보다 문제 해결 과정을 통합적으로 관찰한다.
- LMS 등 디지털 도구를 활용할 수 있으며, 평가 전에 학생이 도구를 다룰 수 있게 한다.

**내용 영역의 배열순서가 교수·학습의 순서를 의미하지는 않습니다.** 학생 상태와 학습
환경을 고려해 내용이나 순서를 재구성할 수 있다고 명시돼 있으므로, 폴더 구조를 교과서
순서로 잡아도 무방합니다.
