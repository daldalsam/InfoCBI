# 단원 대장

**단원끼리 부딪히는지 확인하는 곳입니다.** 축·낱말·활동 동사가 겹치지 않는지,
이미 다룬 것을 또 다루지 않는지, 뒤 단원에 넘긴 것이 무엇인지를 한곳에 모읍니다.

> **`lesson.md`는 이 파일을 베끼지 않습니다.** 자기 줄만 쓰고, 충돌 확인은 여기서
> 합니다. 이유는 `docs/lesson-template.md` 「대장을 베끼지 않는다」.
>
> 렌즈와 일반화 한 줄은 `docs/pedagogy.md` 「단원별 개념 한눈에 보기」에 있습니다
> (최상위 `CLAUDE.md`가 그 표로 커밋을 점검하므로 옮기지 않습니다).

## 표 1. 단원 대장

새 `lesson.md`를 만들면 여기에 한 줄을 더합니다. **비어 있는 칸은 그 관습이
생기기 전에 설계된 단원**입니다 — 소급해서 채우지 않습니다.

| 단원 | 차시 | 이 단원이 맡은 축 | 활동 동사 | 활동 성격 | 활동 이름 | 과제 제목 | 세는 도구 |
|---|---|---|---|---|---|---|---|
| Ⅱ-1-01 `02-data/01-digital-data` | 2 | — | — | — | — | — | 앱 · 패들렛 |
| Ⅱ-1-02 `02-data/02-representation` | 3 | — | — | — | — | — | 앱 |
| Ⅲ-1-01 `03-.../01-problem-state` | 2 | 무엇을 상태로 정의해야 문제를 이어가는가 | 선택하다 | 탐색 | — | — | 1차시 앱 / 2차시 패들렛 |
| Ⅲ-1-02 `03-.../02-abstraction` | 2 | 무엇을 **버려도 되는가**, 버리면 안 되는 선은 어디인가 | 켜다·끄다 | 관찰 | — | — | 앱 |
| Ⅲ-1-03 `03-.../03-expression` | 2 | 남긴 것을 **어떤 형식으로 적어야** 남이 그대로 실행하는가 | 늘어놓다(끼우다·빼다) | 제작 | — | — | 앱 |
| Ⅲ-1-04 `03-.../04-analysis` | 2 | 무엇을 **기준으로 비교해야** 좋고 나쁨을 말할 수 있는가 | 길을 잇다·만들다 | 판정(＋설계) | — | — | 앱 |
| Ⅳ-1-01 `04-ai/01-ai-concept` | 2 | 판정하는 규칙이 **어디서 오는가** | 얹다·내리다 / 찍다·지우다 | 대조 | 어떻게 가려낼까? | `[인공지능 01-N차시]` | 앱 · 패들렛 |
| Ⅳ-1-02 `04-ai/02-data-learning` | 2 | **무엇을 물려받았는가** — 빼놓은 것 | 담다·빼다 | 구성 | 무엇을 보여 줄까? | `[분리배출 02-N차시]` | 앱 |
| Ⅳ-2 실습 `04-ai/03-ai-practice` | 4 | **무엇을 보고 갈랐는가** — 딸려 들어간 것, 특히 나 | 가르치다·시험하다 | 교습(＋대조) | 무엇을 보고 갈랐을까? | `[가르치기 03-N차시]` | 1~3 티처블 머신 / 4 패들렛 |
| Ⅳ-2-04 `04-ai/04-ai-ethics` | 2 | **고치려 들면 무언가 깎인다** — 방안은 무엇을 얼마나 내주기로 정했는지 | 걸다·내주다 | 처분(＋논증) | 무엇을 내줄까? | `[정하기 04-N차시]` (소단원 04 — 대단원 번호와 우연히 같음) | 1차시 **없음(0)** / 2차시 패들렛 |

**⚠ 정정 (2026-08-21).** 「01 선택하다 / 02 켜다·끄다」와 「01 탐색 / 02 관찰」의
주인은 **Ⅲ-1-01·Ⅲ-1-02**입니다. Ⅳ의 `lesson.md` 셋이 이 목록을 베껴 옮기면서
**Ⅱ-1-01·Ⅱ-1-02로 잘못 적었습니다.** 원문 근거는
`03-.../03-expression/lesson.md` 「조작 어휘」와 `04-analysis/lesson.md` 「활동 성격
판정」. 이 표가 맞습니다.

**과제 제목 규칙은 `[소재 소단원번호-N차시]`입니다**(2026-08-25 확정).
**가운데 숫자는 소단원 번호**이므로 한 대단원에 소단원이 늘어도 부딪히지 않습니다.
Ⅱ·Ⅲ는 처음부터 소단원 번호였고, **Ⅳ 넷을 여기에 맞췄습니다** — 대단원 번호로
적던 때에는 `[알고리즘 04-2차시]`(Ⅲ-1-04)와 `[인공지능 04-2차시]`(Ⅳ-1-01)의
「04」가 서로 다른 것을 가리켰고, **학생은 클래스룸 목록에서 이 둘을 나란히 봅니다.**

소재 이름은 여전히 단원마다 다르게 둡니다 — 번호가 갈라 주더라도 목록에서
눈으로 먼저 잡히는 것은 소재 이름입니다.

## 표 2. 이미 다룬 것 — 다시 발견하게 만들지 않는다

여기 있는 것을 뒤 단원에서 다시 «발견»시키면 확인 활동이 됩니다.
**판단의 근거로 쓰는 것은 반복이 아닙니다.**

| 발견 | 어디서 | 뒤 단원 처리 |
|---|---|---|
| 무엇을 잴지(기준)를 정해야 비교가 성립한다 | Ⅲ-1-04 | — |
| 한 숫자로 세면 빠뜨린 쪽의 실패가 가려진다 | Ⅳ-1-02 | — |
| (정확도로 재는 것의 한계 — 위 둘 ＋ Ⅳ-2 실습에서 셋) | Ⅲ-1-04 · Ⅳ-1-02 · 실습 | **네 번째 금지.** Ⅳ-2-04는 숫자를 아예 쓰지 않는다 |
| 편향 — 예시 묶음에서 빼놓은 쪽이 가려진다 | Ⅳ-1-02 | 재발견 금지. 근거로만 |
| 딸려 들어간 것 — 특히 예시를 만든 나 자신 | Ⅳ-2 실습 | 재발견 금지. 근거로만 |
| 규칙은 사람이 정한 약속이다 | Ⅱ-1-02 | Ⅳ-1-01이 **뒤집는 재료**로 씀 |
| 예시로 배운 것은 모르는 것을 모른다 | Ⅳ-1-01 | 실습이 **한 걸음 나아감**(사람이 종류를 만들어 준다) |

## 표 3. 봉인 — 뒤 단원에 넘긴 것

| 무엇 | 봉인한 단원 | 받을 단원 | 상태 |
|---|---|---|---|
| 실제 수집 절차·도구 | Ⅳ-1-02 | Ⅳ-2 실습 | ✅ 열림 |
| 윤리적 해결 방안 구상 (9정04-05) | Ⅳ-1-02 · Ⅳ-2 실습 | Ⅳ-2-04 | ✅ 열림 |
| 「누가 데이터를 만드는가」 | Ⅳ-2 실습 4차시 | Ⅳ-2-04 | ✅ 열림 |
| **동의와 권리의 이름** — 개인정보 자기결정권·초상권·저작권 | Ⅳ-2 실습 · Ⅳ-2-04 | **Ⅴ-2 (9정05-03)** | 🔒 **닫힘 — 열지 말 것** |
| **학급 합의문·실천 서약·표결 절차** | Ⅳ-2-04 | **Ⅴ-2 (9정05-02)** | 🔒 **닫힘** |

**Ⅴ-2 설계를 시작할 때 이 표의 닫힌 둘을 먼저 봅니다.** 9정04-05와 9정05-02는
동사가 거의 같아서(*「구상한다」* / *「민주적으로 논의하고 수립한다」*) 선이 필요합니다 —
**Ⅳ-2-04는 「데이터 묶음」에 조건을 걸고 모둠별 제안으로 끝내고, Ⅴ-2는 「내 행동」의
규칙을 학급 합의로 모읍니다.** Ⅴ는 4차시가 하한선이라 앞 단원이 그 몫을 먹으면
9정05-02가 성립하지 않습니다.

## 표 4. 뒤집은 판단 — 되돌아오지 않게

| 무엇을 | 언제 | 왜 |
|---|---|---|
| 렌즈 「표현」 → 「추상화」 (Ⅲ-1) | Ⅲ-1-01 | 표현이 04(효율성 비교)에 닿지 않아 중단원을 묶지 못함 |
| 렌즈 「표현」 → 「학습」 (Ⅳ) | Ⅳ-1-01 | 표현으로 보면 **새로 열리는 것이 없음** |
| Ⅴ 6차시 → **4** / Ⅱ-2 6 → **8** | 2026-08 총괄 | 성취기준 1개당 차시 불균형(Ⅱ-2가 기준 4개에 1.5차시) |
| 소단원 02(소리) 탈락 | Ⅳ-2 실습 | **실제 수업에서 학생 간 간섭**(2026-08-20). 설계 판단으로 뒤집지 않음 |
| 자세(모션) 프로젝트를 본체로 | Ⅳ-2 실습 | 축이 흐려지는 게 아니라 **한 단 올라감** |
| 자작 앱을 만들지 않음 | Ⅳ-2 실습 · Ⅳ-2-04 | 조작과 즉시 반응이 도구·판단 안에 이미 있음 |

| `lesson.md`에서 대조표를 걷어내고 이 파일로 | 2026-08-21 | 분량이 단원 수에 비례해 늘고 사본이 갈라졌음 |

## 표 5. 낱말 배정

같은 낱말이 단원마다 다른 뜻으로 쓰이는 것을 막습니다.

| 낱말 | 어디 | 뜻 |
|---|---|---|
| **규칙** | Ⅱ-1-02 | 대상과 비트를 잇는 **약속** |
| | Ⅲ-1-01·02 | 판의 **제약** |
| | Ⅲ-1-03 | 실행자 안에 **숨은 해석** |
| | Ⅳ-1-01 | **판정 조건** |
| | Ⅳ-2 실습 | **학급 규칙** — 「찍기 전에 물어본다」 |
| | **Ⅴ-2** | 🔒 **예약.** 9정05-02의 성취기준 낱말이라 **Ⅳ-2-04는 쓰지 않는다** |
| **분류** | Ⅱ-2 `03-structuring` | 데이터를 갈라 저장하는 일 |
| | Ⅳ-1-02 | 카드에 **이미 붙어 있는 정답**(♻/■). 학생은 고르기만 |
| **클래스** | Ⅳ-2 실습 | 티처블 머신 화면의 **판정 갈래.** 학생이 이름까지 정하고 하나 더 만들 수도 있다 |

| **종류** | Ⅳ-1-02 | 카드의 **재질 갈래** — 종이·플라스틱·유리… |
| | Ⅳ-2 실습 일반화 2 | 「클래스」의 **일반화용 낱말.** 일반화 문장에 도구 이름을 넣지 않기 위해 갈라 씀. **화면에서 만지는 것은 「클래스」, 문장으로 남기는 것은 「종류」** |
| **방안** | Ⅳ-2-04 | 데이터를 **모으고 쓰는 일에 붙이는 조건** |
| | Ⅴ-2 | **실천 방안** — 내가 지킬 행동 |
| **판** | Ⅲ-1-01·02·03 | **문제의 상태** — 강 건너기 판 |
| | Ⅳ-1-01 | **화면 한쪽** — A판·B판 |

## 갱신 규칙

- 새 `lesson.md`를 만들면 **표 1에 한 줄**, 필요하면 표 2~5에 줄을 더합니다.
  **없으면 커밋을 멈춥니다**(최상위 `CLAUDE.md`의 `pedagogy.md` 점검과 같은 취급).
- 판단을 뒤집었으면 **표 4에 한 줄.** 근거를 `lesson.md` 본문에 문단으로 쓰지 않습니다.
- 표가 길어지는 것은 정상입니다 — **여기 한 곳만 길어지고 `lesson.md`는 안 길어지는
  것**이 이 파일의 목적입니다.
